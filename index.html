Codex • OpenAI's AI coding agent • Harness

Codex is a model inside a harness.

The model generates text. The harness gives it tools, context, a sandbox with approval rules, and a loop, and that is what turns text into real work in a codebase.

Model: thinks, plans, and decides which tools to call.
Harness: runs the actions and feeds the results back into the context.
Context: chat history, search results, file contents, and AGENTS.md.
Result: an AI that reads, changes, runs, and explains code.

Codex is the coding agent in the ChatGPT and OpenAI ecosystem.
Simple definition:
A harness is the operating environment around the model that turns text generation into real actions.

What this means

The useful mental model is not "the AI magically changes code." It is "the model asks, the harness acts."

Without a harness

  • Text generation only
  • No real file access
  • No command execution

With a harness

  • Read, search, edit, shell, Git
  • Sandbox and approval levels as a safety net
  • Session memory and flow control

Why it matters

  • The same model produces very different results in different harnesses
  • Tool design and context quality decide the outcome
  • Good systems beat vague AI magic

Why a good harness matters so much

Same model, same benchmark, different harness. OpenAI tripled the ARC-AGI-3 score of GPT-5.6 Sol by changing two settings.

What the curve shows

  • Two harness settings: keep reasoning across turns and compaction instead of a hard context cutoff.
  • Result: about 38% instead of about 13%, using roughly one sixth of the tokens.
  • The model is the same in both runs. The difference comes entirely from the environment around it.
  • That is why it pays to understand and configure the harness.

Source: OpenAI — "How two settings tripled our ARC-AGI-3 scores"

Harness architecture

The harness sits between the language model and the real environment.

Core idea

  • The model only knows what is in its context.
  • The harness decides which tools exist and how they are described.
  • After a tool call, the harness performs the real action inside the sandbox.
  • The result goes back into the context so the model can keep working.
  • This loop is what makes Codex feel agentic.

The action loop

Every useful coding agent follows roughly this pattern.

1

User gives a task

Example: find a bug, fix it, and explain the change.

2

Model picks a tool

It searches, reads files, checks tests, or runs a command.

3

Harness executes

The action happens in the real environment, filtered through the sandbox and approval rules.

4

Output lands in the context

The model "sees" the result and decides the next step.

5

Loop until done

Read, change, run, verify, explain.

Codex in one sentence:

A language model becomes a practical coding agent once a harness gives it tools, context, sandbox boundaries, memory, and a loop for finishing tasks.

Core components

The building blocks of the Codex harness.

T

Tool system

Read, search, and edit files, run shell commands, use Git, plus external tools through MCP servers.

C

Context engine

Loads what is needed instead of dumping the whole repo into the context. Long sessions get condensed (compaction).

S

Sandbox & approvals

Two separate controls: the sandbox limits what a command may do, the approval policy decides when Codex asks first.

H

Sessions

History and task state persist. You can resume a session instead of starting cold.

O

Orchestration

Drives the cycle from prompt to tool call to result to the next action.

M

Project memory

AGENTS.md preloads rules, structure, and expectations. Files closer to the working directory take precedence.

Sandbox and approvals

The part of the harness that makes Codex safe enough to actually let it work. Sandbox mode and approval policy are set independently.

Sandbox modeWhat is allowed
read-onlyRead only. Edits, commands, and network access need approval.
workspace-write
Default		Read, edit, and run commands in the working directory. Network access is off by default.
danger-full-access
Risky		No sandbox limits. Only sensible in environments that are already isolated, such as containers or CI.
Approval policyWhen Codex asks
untrustedOnly known-safe read operations run automatically; everything else needs confirmation.
on-requestCodex asks when it wants to leave the sandbox, for example for network access or writing outside the workspace.
neverNo prompts. Codex works autonomously within the sandbox limits.

macOS

Seatbelt profiles via sandbox-exec, matched to the selected sandbox mode.

Linux

Isolation via bwrap (Bubblewrap) plus seccomp filters.

Windows

Through WSL2, where the same Linux sandbox rules apply.

How the harness scales

When a task gets too big for one context window, the harness splits the work instead of overloading the model.

More work in parallel

  • Subagents: a manager breaks the task down and hands subtasks to workers, each with its own context window.
  • Git worktrees: locally, every parallel task gets its own working copy of the same repo so the changes don't collide.
  • Compaction: long sessions get condensed instead of stopping at the context limit.

Plug in more capabilities

  • MCP: external tools and data sources are added as extra tools.
  • Skills & plugins: reusable instructions and extensions the harness loads when needed.
  • Configuration: config.toml for model, sandbox, approvals, and MCP servers; AGENTS.md for project rules.

The model inside the harness

Model and harness are separate parts: you can swap the model without changing anything else. Version numbers change every few weeks, the three tiers stay.

A

Astra

The flagship. For the hardest tasks, when the other models get stuck.

S

Sol

The everyday workhorse for complex coding: close to top performance at a much lower price.

L

Luna

The fast, economical option for simpler tasks and many runs.

Reasoning effort as a dial

Besides the model, you can set how much the model thinks, from low to maximum. More reasoning effort helps with hard tasks but costs time and tokens. That's the point: model choice and reasoning depth are harness parameters, not fixed properties of the AI.

Key takeaways

What should stick.

1. Not just a model

Codex is model + harness.

2. Context is everything

The model only knows what the harness gives it.

3. Limits enable autonomy

Sandbox and approvals are what make it reasonable to let the agent run.

4. It's system design

The magic is in the architecture, not in wizardry.
